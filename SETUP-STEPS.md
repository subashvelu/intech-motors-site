# Set up your GitHub profile (about 20 minutes)

## A. Create the profile README repo
1. github.com → **+** → **New repository**.
2. Repository name: **subashvelu** (it must be exactly your username). Choose **Public**. Tick **Add a README file**. Create it.
3. Open the repo, then **Add file → Upload files**. Upload `README.md` and the `assets` folder from the `profile` folder of this kit, replacing the existing README. Commit.
4. Open the file and replace the lines marked `EDIT`: your LinkedIn link and email. Check the name in `assets/banner.svg` (search for "Subash V").
5. Visit github.com/subashvelu. Your new profile appears at the top.

## B. Upgrade the project README
1. Copy `intech-motors-site/README.md` from this kit over the one in your project folder.
2. Take 3 screenshots (home page, estimate PDF, owner app) and save them in a `docs` folder. Un-comment the three image lines near the top of the README.
3. `git add .` → `git commit -m "docs: professional README with architecture and security notes"` → `git push`.
   (Markdown files are not uploaded to your website, so this does not change the live site.)

## C. Make the repo page look professional
1. Open the repo, click the **gear icon** next to **About**.
2. **Description:** `Car workshop website on AWS (S3 + CloudFront) with GitHub Actions CI/CD, OIDC, CloudFormation, and an offline billing PWA`
3. **Website:** `https://d166dz9n7bj9t4.cloudfront.net`
4. **Topics:** `aws` `cloudfront` `s3` `github-actions` `cloudformation` `oidc` `devops` `ci-cd` `pwa` `infrastructure-as-code`
5. Save.

## D. Profile settings (github.com/settings/profile)
- **Name**, short **Bio** (example: `Aspiring Cloud & DevOps Engineer | AWS | CI/CD | Terraform (learning)`), **Location:** Chennai, **Website:** your live site or LinkedIn.
- Upload a clear, professional **profile photo**.
- On your profile click **Customize your pins** and pin your best repos (project 1 now, more later).

## E. Habits that make the profile look active
- Commit small changes often (green squares show consistency).
- One repo per project, each with a README, diagram and live link.
- Write what you learned in the README. Recruiters read that part.
